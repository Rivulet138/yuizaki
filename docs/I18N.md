# Internationalisation (i18n)

The renderer ships three locales: `zh-CN` (source of truth), `en-US`, `ja-JP`.
All UI text must go through `t()` — a literal Chinese string in a component is a
bug, because it is rendered unchanged for English and Japanese users.

## Runtime

`electron/src/renderer/i18n/index.ts`

- `messages` holds the three locale tables. It is assembled from message modules
  plus the inline literals that predate the module split.
- `resolvedMessages` adds the ja-JP patch layer (`jaOverrides.ts`) on top.
- `t(key, params?)` looks up `locale→key`, falls back to `zh-CN`, then to the raw
  key so a missing key stays visible instead of rendering empty.
- `setLocale()` persists the choice through the settings store and updates
  `<html lang>`.
- `localeTables` (exported) exposes the resolved tables for tests.

The `t()` function reads `reactive` locale state, so components re-render on a
language switch without extra wiring.

## Message modules

Panel text lives in `i18n/<panel>Messages.ts`, built with `definePanelMessages()`
(`i18n/definePanelMessages.ts`). The helper infers the key union from the three
tables, so **a key missing from one locale is a compile error**, and so is a key
that only one locale still carries.

The renderer currently ships one module per surface:

| Module | Surface |
| --- | --- |
| `chatMessages`, `chatPanelMessages` | conversation view and composer |
| `toolPanelMessages` | capabilities & tools |
| `pluginPanelMessages` | plugin management |
| `governancePanelMessages` | agent governance and connectors |
| `overviewPanelMessages`, `agentTracePanelMessages` | system overview and traces |
| `infrastructureMessages` | services & resources |
| `petControlPanelMessages`, `promptAndPetPanelMessages` | pet control, relationship history, prompt editor |
| `memoryPanelMessages`, `memoryComponentsMessages` | memory panel and its cards |
| `settingsPanelMessages`, `settingsSectionsMessages` | settings shell and its sections |
| `deployMessages`, `connectorPaneMessages` | deployment and connector cards |
| `onboardingMessages`, `proactiveMessages`, `productMetricsMessages` | onboarding, proactivity, metrics |
| `errorMessages` | backend error catalog (`shared/errors/describe-error.ts`) |
| `runtimeMessages` | store / audio / pet-renderer runtime text |
| `appChromeMessages` | sidebar, shared components, dialogs, curated skills |
| `keyGapMessages` | keys components used before any table defined them |

```ts
export const exampleMessages = definePanelMessages({
  'zh-CN': { 'example.title': '示例' },
  'en-US': { 'example.title': 'Example' },
  'ja-JP': { 'example.title': '例' },
})
```

Wire a new module in `index.ts` in three places (one import, three spreads):

```ts
import { exampleMessages } from './exampleMessages'
// inside messages:
'zh-CN': { ...exampleMessages['zh-CN'], /* … */ },
'en-US': { ...exampleMessages['en-US'], /* … */ },
'ja-JP': { ...exampleMessages['ja-JP'], /* … */ },
```

## Guardrails

| Gate | Where | Catches |
| --- | --- | --- |
| Type parity | `definePanelMessages()` + `npm run type-check` (vue-tsc) | a key defined in one locale only |
| Table invariants | `i18n/coverage.test.ts` | missing keys, empty values, placeholder drift, Chinese left in `en-US`, simplified characters left in `ja-JP` |
| Module invariants | `i18n/message-modules.test.ts` | same checks per module, before the spread |
| Lookup behaviour | `i18n/lookup.test.ts` | a defined key rendering as itself, broken interpolation |
| Hardcoded text | `scripts/i18n_inventory.py` | Han characters in renderer sources outside `i18n/` |

Run the inventory:

```bash
python scripts/i18n_inventory.py            # summary + biggest offenders
python scripts/i18n_inventory.py --json out.json
python scripts/i18n_inventory.py --max-cjk N # non-zero exit above a budget
```

## Conventions

- Key namespaces are per panel: `pluginPanel.*`, `tools.*`, `governance.*`,
  `trace.*`, `overview.*`, `petControl.*`, `memory.*`.
- `{placeholder}` names must match across locales; the tests enforce it.
- Element Plus props need binding (`:label`, `:placeholder`, `:empty-text`,
  `:description`, `:title`, `:aria-label`), otherwise the literal is ignored.
- Values that come from the backend (status codes, ids, paths) are not
  translated; map them to keys first.
- Comments stay English so the source reads the same for every contributor.
- Language endonyms (`language.zh`, `language.japanese`) stay in their own
  script; the coverage test exempts them from the "no Chinese in en-US" rule.

## Adding a locale

1. Add the tag to `Locale` and `supportedLocales` in `index.ts`.
2. Add the table to every message module — `definePanelMessages` will refuse a
   partial table.
3. Extend `coverage.test.ts` / `message-modules.test.ts` locale lists.
4. Add the option to the language picker (`I18nPanel.vue`).

## Built-in prompts

`promptDefaultsMessages.ts` holds the two workspace system prompts per locale.
The store resolves them with `defaultWorkPrompt()` / `defaultDailyPrompt()` and
recognises a stored prompt that matches **any** locale's built-in text as
"not customised" (`isBuiltinWorkPrompt`). A locale switch therefore re-localizes
the default prompts of every workspace and leaves edited prompts alone.

## Known remaining work

`python scripts/i18n_inventory.py` covers `electron/src/renderer` **and**
`electron/src/shared`; it currently reports four files, all intentional:

- `renderer/state/settingsStore.ts` — TTS enum tokens (`质量优先`, `智能切分`, …)
  persisted to the backend and compared in `python/modules/tts/`.
- `renderer/net/socketClient.ts` — one Chinese code comment.
- `shared/input-bindings.ts` — `mouseButtonLabel()`, used only by the main process
  (tray/HUD), which has no i18n layer; the renderer resolves the name through
  `misc.mouseSideButton` instead.
- `shared/pet-control-validator.ts` — `默认|普通` inside a regex that matches
  manifest expression ids, not display text.

Everything a user can read goes through `t()`. `npm run test:unit`
(`i18n/coverage.test.ts`, `i18n/message-modules.test.ts`, `i18n/lookup.test.ts`,
`navigation/navigation-contract.test.ts`) plus the CI `Audit i18n coverage` step
hold the line: the step fails when hardcoded Chinese grows past its budget, so a
new panel cannot land untranslated.
